# Claude 信任评分：研究结论、规则与接入

核对日期：2026-10-15。页面入口：`/frontend/claude.html`，首页导航为“Claude 评分”。

## 查到的实际实现

参考页面：[Net.Coffee Claude 检测](https://ip.net.coffee/claude/)。公开脚本为 [claude-page.js](https://ip.net.coffee/claude/claude-page.js?v=20260916a)。本项目独立实现页面和规则，没有复制该站脚本。

- 浏览器先请求 `https://claude.ai/cdn-cgi/trace`，从 `ip=` 字段读取这次连接的出口；失败时不显示评分。2026-10-15 的一次 HTTP 核对返回 200，带 `Access-Control-Allow-Origin: *`。这不是具有长期兼容承诺的业务 API，浏览器、网络或站点策略变化均可能使其失效。
- 随后调用该站自己的 `/api/iprisk/{ip}`，读取 `trust_score`；分数不是从 Claude 回显接口获得的。公开前端没有后端评分公式。
- 前端注释称按 CIDR 计算、缓存 365 天；这是源代码注释，尚未独立验证实际缓存时长。
- 两次只读抽样中，查询 `1.1.1.1` 返回 `ip=1.1.1.2`、`cidr=1.1.1.0/24`、41 分；查询 `8.8.8.8` 返回 63 分。这些只是该站当次返回，不能解释为精确 IP 的事实或 Claude 官方结果，也不足以反推公式。
- 前端将其自定义受限地区名单强制置为 0 分。本站将地区适用性与 IP 风险分离，并链接官方地区政策，不把“地区不支持”解释为 IP 不干净。
- 参考站暴露了查询接口，但本次没有找到其公开 API 接入协议、配额或稳定性承诺，因此不将它作为本项目的生产依赖。

Anthropic 的[位置使用说明](https://privacy.claude.com/en/articles/11186740-does-claude-use-my-location)确认其会使用 IP 和其他信号进行粗粒度位置判断及反滥用。这不能推导出一个公开的 0–100 信任分。此次检索未找到 Anthropic 官方提供的此类评分接口。

## 当前规则 boke-ip-v1

这是本项目自主设定、尚未通过账号结果校准的参考规则，不是对 Net.Coffee 的数值复刻，也不是登录成功率或封号概率。

| 维度 | 数据字段 | 扣分 |
| --- | --- | --- |
| 匿名网络 | is_tor / is_proxy / is_vpn | 60 / 35 / 20，同时命中取最大值 |
| 该 IP 的滥用标记 | is_abuser | 25 |
| 数据中心 | is_datacenter | 15 |

`总分 = max(0, 100 − 匿名网络扣分 − 滥用扣分 − 机房扣分)`。

5 个必需字段都必须是布尔值。缺失、null、字符串 `"false"` 或匿名版响应均不能被当作安全，总分留空。爬虫标记仅展示。整个公司/ASN 的 `abuser_score`、地理位置、语言、时区和指纹不扣分。无机房标记也不直接判定为住宅。

- 100：未命中所查风险。
- 80–99：较少风险信号。
- 50–79：存在风险信号。
- 0–49：较多风险信号。

例如 VPN + 机房 = 65；Tor + 代理 + VPN 只扣 60；Tor + 滥用 + 机房 = 0。UI 的“先看评分示例”明确使用虚构样例，完全不查询外网。

## 免费数据源

选择 [ipapi.is 官方 API](https://ipapi.is/developers.html)。按 [2026-10-15 核对的免费额度说明](https://ipapi.is/free-tier.html)：

- 无 Key：每天 30 次简化查询，不含本功能所需的风险标记。
- 免费账号 Key：每天 1,000 次完整查询，官方注明可商用、无需付款信息。
- Key 只保存在服务器；本站通过 HTTPS POST JSON 传给固定的 `api.ipapi.is`，不放进浏览器、URL、Git 或客户端日志。

额度和规则可能变化，部署前以服务商页面为准。注册或付费需要账号持有人自行完成，本次没有创建第三方账号。

## 配置与运行

1. 在 [ipapi.is](https://ipapi.is/free-tier.html) 申请免费账号，从 Dashboard 获取 Key。
2. 在项目目录复制 `.env.example` 为 `.env`，只在本机文件填写 `BOKE_IPAPI_KEY`。`.env` 已被 Git 忽略；不要把真实 Key 发到聊天、PR 或截图中。
3. 构建并启动包含本次代码的本地镜像：

```bash
docker compose -f compose.yaml -f compose.claude.yaml up -d --build
```

默认入口为 `http://127.0.0.1:18088/frontend/claude.html`。基础发布镜像 1.2.0 不含本次新代码，所以覆盖文件明确使用本地构建。若现有服务占用了 18088，先自行选择空闲映射端口，避免替换正在使用的实例。

在页面点击“检测 Claude 出口”，确认来源显示“Claude 浏览器出口”。如果自动识别失败，可以输入公网 IP，但结果会保留“手动输入”来源说明，不冒称已验证的 Claude 出口。

已有其他部署可在服务端配置：

| 配置 | 用途 |
| --- | --- |
| BOKE_IPAPI_KEY | API Key；没有时服务返回未配置，总分留空 |
| BOKE_IPAPI_KEY_FILE | 可选的服务器密钥文件路径，优先于环境变量；文件不要放到网站目录 |
| BOKE_RISK_DAILY_LIMIT | 本实例 UTC 每日上游调用预算，默认 900，允许 1–1,000 |
| BOKE_RISK_STATE_DIR | 非网站目录的可写缓存目录；默认临时目录，建议持久化 |

覆盖 Compose 持久化 `/var/lib/boke-risk`，权限归 www-data。单 IP 结果缓存有效期 1 小时，最多 256 条，过期记录在后续查询时清理。不记录账号/浏览器指纹。读取配置和查询响应均 `no-store`。

每实例每分钟最多 30 次，每个直接连接来源每分钟最多 5 次。不会相信用户传入的 X-Forwarded-For；反向代理后面可能共用该 5 次限制，应结合部署的可信代理方案调整。一次仅允许一个上游查询；忙时快速返回 503，不排队也不自动重试。上游 429 暂停新查询至 UTC 次日，401/403 暂停 5 分钟；可继续读取未过期缓存。每日预算先预留再发请求，额度文件使用独立锁与原子替换。

这些是防止误刷额度的应用限制，不代表 DDoS 防护。多副本部署必须共享协调后的配额或分别分配预算；删除缓存卷会重置本地计数，服务商的实际额度不会重置。

## 验证与边界

离线检查不调用真实风险服务，也不消耗免费 API 配额：

```bash
php tests/claude-risk-core.php
php tests/claude-risk-http.php
node tests/claude-risk-browser.cjs
```

HTTP 测试使用本机临时 PHP 服务和测试专用 HTTPS 模拟器；推荐在 `--network none` 容器内运行。浏览器检查默认针对本机 18102，需先启动独立预览；所有第三方请求均被测试夹具拦截。可以用 `BASE_URL`、`PLAYWRIGHT_MODULE`、`BROWSER_CHANNEL` 选择本机测试环境。

当前已覆盖规则组合、数据缺失、IPv6、地址不匹配、缓存、每日预算、频率限制、上游错误熔断、取消、手动来源、XSS 文本渲染和手机布局。没有 Key 时无法验证真实风险数据查询；离线样例的分数不是对样例 IP 的真实判断。尚未发布镜像或修改生产服务。
